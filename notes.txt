======================================================================
DETAILED PROJECT CONTEXT
======================================================================

PROJECT

Plumville is a Minecraft Bedrock metro and world-planning project.

The repository currently has three interacting tracks:

1. Private Tk desktop application
   - Main launch path: `plumville_app.py` -> `metro_stops.py`
   - Core legacy application: `legacy_core.py`
   - Extension orchestration: `ui_extensions.py`
   - Private authoring, routing, editing, world-map control, and exports

2. Public browser viewer
   - Folder: `docs/`
   - GitHub Pages read-only viewer
   - Current data file: `docs/metro_network.json`
   - Public changes can be tested at desktop width with localhost
   - Phone-specific work requires a push and is currently on hold

3. World-generation backend
   - Package: `worldgen/`
   - Docker/Bedrock orchestration, chunk loading, rendering, and cache state
   - Large runtime data must remain ignored and private

CURRENT DATA REALITY

- `docs/metro_network.json` is currently shared by desktop and public code.
- A future canonical/public split is planned but not part of D01.
- Do not relocate the metro dataset during desktop stabilization.
- Do not expose private fields in public output.

CURRENT EXTENSION ORDER

`metro_stops.py` calls `ui_extensions.apply()` once.

The latest ui_extensions.py currently applies:

- worldgen_speedups
- metro_station_extensions
- poi_extensions
- its own route-panel wrapper
- path_rendering
- path_detection
- world_map_overrides
- desktop_improvements

This order is high risk because several modules monkey-patch methods on
MetroMapViewer. D01 must verify the order and idempotence instead of assuming
the wrappers compose safely.

CURRENT DESKTOP DRAFT

The latest main already contains `desktop_improvements.py`. It includes draft
implementations for:

- route auto-fit
- Fit Route
- completed-worldgen control hiding
- removal of path detection from the normal popup
- an Advanced / Experimental section

The user reports that the prior generated update had errors and never ran as
intended. Therefore:

PATH DETECTION POLICY

WORLDGEN COMPLETION POLICY

- Completed means trustworthy full coverage, not merely a displayed “100%”
  string.
- Hide only active generation controls.
- Keep visibility, status, analysis, validation, and export.
- Reappear if the render/cache/config no longer proves completion.

PUBLIC MOBILE HOLD

No new phone-specific behavior should be implemented until the user can push
and test a published build again.

Allowed public work during the hold:

- desktop-browser localhost fixes;
- automated public validation;
- regressions that can be reproduced without phone testing.

Not allowed during the hold:

- new mobile navigation;
- safe-area changes;
- sticky-map redesign;
- bottom-sheet work;
- orientation-specific tweaks based only on guesses.

DESIGN LANGUAGE

Minecraft Control Panel / MMCP:

- dark charcoal surfaces;
- crisp rectangles and very small radii;
- restrained Minecraft-inspired borders and texture;
- modern readable body text;
- pixel/mono accents for headings and badges;
- emerald for ready/active;
- gold for warnings or landmarks;
- redstone for errors;
- diamond blue for focus/selection;
- circle means line;
- diamond means station;
- larger or double diamond means junction;
- Mt. Phosphagos remains a gold-outlined landmark.

STATION ABBREVIATIONS

Authoritative corrected examples:

- Isle of Whales = IWH
- Slimin = SLI
- Triarchidia = TRI
- Everly = EVL
- Michael = MCL

Rules:

- 2–5 characters
- alphanumeric
- uppercase default
- preserve explicit user capitalization
- duplicates warn
- never silently overwrite
