PURPOSE

This file ranks project files by how much useful checklist work can be
completed by changing that file, while also accounting for implementation
risk, testability, and whether the user can verify the result immediately.

Update this file after every implementation run.

SORTING RULES

1. Active high-value files first.
2. Within a similar value, prefer changes that are easy to test on web/mobile.
3. High-risk monoliths may rank lower even when they contain more total logic.
4. Completed file-level work moves to the COMPLETED FILE WORK section.
5. Re-rank after every run because dependencies and leverage will change.
6. A one-file production change may still require a separate test-file update.
